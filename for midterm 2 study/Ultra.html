Haskell & Functional Programming

  1. Q: A list [1, 2, 3] in Haskell is syntactic sugar for...

    1. 1 : 2 : 3 : [] which is equivalent to (([] : 1) : 2) : 3
    2. 1 : 2 : 3 which is equivalent to 1 : (2 : 3)
    3. 1 : 2 : 3 which is equivalent to (1 : 2) : 3
    4. 1 : 2 : 3 : [] which is equivalent to 1 : (2 : (3 : []))

    A: 1 : 2 : 3 : [] which is equivalent to 1 : (2 : (3 : []))

     

  2. Q: Which kind of recursion is an important concept in functional programming?

    1. head recursion
    2. neck recursion
    3. arm recursion
    4. leg recursion

    A: tail recursion

     

  3. Q: What does it mean that Haskell is a pure functional programming language?

    A: The evaluation of expressions has no side-effects.

Definitions & Concepts

  1. Q: What is/are: Alan Turing?

    A: Famous for the Turing machine; showed the limits of computation. The Turing machine is the definition of computable functions.

     

  2. Q: What is/are: Alonzo Church?

    A: Invented the lambda calculus in the 1930s.

     

  3. Q: What is/are: a λ-term?

    A: A variable (x, y, z...), an application P Q, or a λ-abstraction λx. P.

     

  4. Q: What is/are: a redex?

    A: A reducible expression: an application of the form (λx. body) argument — a lambda expression you can reduce.

     

  5. Q: What is/are: β-reduction?

    A: The process of calculating a result from the application of a function to an expression, by substituting the argument for the parameter.

     

  6. Q: What is/are: α-conversion?

    A: Renaming bound variables, e.g. λx. x → λy. y. It does not change the meaning of the expression.

     

  7. Q: What is/are: normal form?

    A: A lambda expression with no redex, so no further β-reduction is needed.

     

  8. Q: What is/are: computation (in the λ-calculus)?

    A: The reduction of a lambda expression to normal form.

     

  9. Q: What is/are: the Church-Rosser theorem?

    A: If an expression has a normal form, it is unique, no matter the order of reduction steps. But some evaluation strategies may take longer or never find it.

     

  10. Q: What is/are: evaluation strategies?

    A: Haskell prefers leftmost/outermost first (normal order); the other is rightmost/innermost first (applicative order).

     

  11. Q: What is/are: applicative order / call-by-value?

    A: Rightmost/innermost redex first. Call-by-value is similar to applicative order, but does no reductions inside lambda abstractions.

     

  12. Q: What is/are: normal order / call-by-name?

    A: Leftmost/outermost redex first. Call-by-name is similar to normal order, but stops at WHNF.

     

  13. Q: What is/are: call-by-need?

    A: Call-by-name + memoization: remembers values it has already computed. E.g. in (2+1) + (2+1) the second (2+1) is not recomputed.

     

  14. Q: What is/are: lazy evaluation?

    A: Also known as call-by-need: evaluation takes place only when the value is needed, and only computes what is necessary.

     

  15. Q: What is/are: generic programming?

    A: Writing algorithms in terms of types that are specified as parameters during instantiation or invocation (type parameters & interfaces in C#, templates in C++, macros/void* in C, polymorphic types & type classes in Haskell).

     

  16. Q: What is/are: memory allocation (the two kinds)?

    A: Static and dynamic.

     

  17. Q: What is/are: static memory?

    A: Fixed size during the process, allocated before the program runs; holds global/static variables and code. Contains the BSS, Data, and Text segments.

     

  18. Q: What is/are: dynamic memory?

    A: Allocated during runtime. The two kinds are the stack and the heap.

     

  19. Q: What is/are: the stack?

    A: Automatic. Holds local variables and return addresses; fixed and limited size; makes function calls and recursive calls possible.

     

  20. Q: What is/are: the heap?

    A: Manual. Used for large data or data whose size is only known at runtime; objects created with new go on the heap.

     

  21. Q: What is/are: allocating memory in C vs C++?

    A: C: malloc to allocate, free to deallocate. C++: new and delete. new calls a constructor (malloc doesn't); delete calls a destructor (free doesn't). Forgetting free/delete causes a memory leak.

     

  22. Q: What is/are: the Data segment?

    A: Initialized static variables, e.g. a global int y = 5;.

     

  23. Q: What is/are: the BSS segment?

    A: "Block Starting Symbol": statically-allocated variables that are declared but not initialized, e.g. a global int x;.

     

  24. Q: What is/are: the Text segment?

    A: The program code (machine instructions). It is static, so the running program doesn't modify it.

     

  25. Q: What is/are: an iterator?

    A: An object used to traverse containers (e.g. arrays or lists), enumerating the elements as a sequence. Also known as an enumerator.

     

  26. Q: What is/are: a coroutine?

    A: A generalization of a subroutine: a subroutine has one entry point (and can exit in several places), while a coroutine has multiple entry points and multiple exit points.

     

  27. Q: What is/are: a generator?

    A: A coroutine that yields a sequence of values. Unlike a subroutine, which returns one value on exit, a generator can yield multiple values without terminating. Can be used to implement iterators.

     

  28. Q: What is/are: a pipeline (modularization)?

    A: Processing one value at a time through each function in turn.

     

  29. Q: What is/are: how Haskell modularizes stream processing?

    A: With lazy evaluation and lists as generators, e.g. sum (square generate) or using $.

     

  30. Q: What is/are: how Python and C# modularize stream processing?

    A: With yield in each function: Python uses yield; C# uses IEnumerable<T> return types and yield return.

     

  31. Q: What is/are: how C modularizes stream processing?

    A: With pipes on the command line, e.g. ./do generate | ./do square | ./do sum.

     

  32. Q: What is/are: the difference between a list and a set?

    A: Lists are ordered and can contain duplicates; sets only have unique elements.

     

  33. Q: What is/are: the imperative paradigm?

    A: Step-by-step instructions. Includes procedural (e.g. C) and object-oriented (e.g. Java, C#) programming; C++ and Python mix both.

     

  34. Q: What is/are: the declarative paradigm?

    A: Describe the problem in a specification language and let the software compute it. Includes functional (Haskell, LINQ; no side effects, immutable variables) and logic (Prolog) programming.

     

  35. Q: What is/are: syntax?

    A: Which character sequences are valid programs? (Does it compile?)

     

  36. Q: What is/are: semantics?

    A: Denotational semantics: what does a program mean / what is it modeling? Operational semantics: what does a program do / which instructions does it execute when it runs?

     

  37. Q: What is/are: soundness (of an operational semantics)?

    A: An operational semantics is sound (with respect to a denotational semantics) if the operational evaluation of expressions preserves their denotational meaning.
